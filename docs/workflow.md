# 七阶段工作流深度解析

本文档详细解析 **VibeCoding — Idea to Product** 的 7 个阶段，包括每个阶段的目标、流程、产出物和设计理由。

---

## 阶段一：产品定位

### 目标
充分理解开发者的产品意图，产出可落地的 PRD。

### 流程
1. Claude 依次提出 8 个关键问题（每次 1-2 个）
2. 开发者回答后，Claude 整理成结构化 PRD 草稿
3. 逐项确认，最终生成 `docs/prd.md`

### 关键问题

| 问题 | 目的 |
| ------ | ------ |
| 目标用户是谁？ | 明确用户画像 |
| 使用场景是什么？ | 理解上下文环境 |
| 解决什么问题？ | 定义核心价值 |
| 产品形态？ | 确定技术选型方向 |
| 核心功能？ | 优先级排序 |
| 成功指标？ | 量化验收标准 |
| 预期用户量？ | 影响架构设计 |
| UI 风格？ | 设计方向参考 |

### 设计理由
在 AI 编程中，最大的风险是"方向性错误"——AI 朝着错误的方向生成了大量代码。本阶段通过结构化提问，确保在编码前就锁定了产品方向。

---

## 阶段二：UI 原型设计

### 目标
将需求转化为可视化的交互原型，并沉淀设计规范。

### 流程
1. **布局方案选择** — 3 种布局方案供选择
2. **交互流程确认** — Mermaid 流程图 + 审查
3. **风格确认** — 2-3 套配色方案
4. **高保真原型** — 可交互的 HTML/CSS/JS
5. **设计规范** — 沉淀为 `docs/design.md`

### 设计理由
视觉反馈是发现需求漏洞最有效的方式。用户在看到原型之前，往往无法准确描述自己想要什么。本阶段通过在编码前"看到"产品，大幅降低返工成本。

---

## 阶段三：技术方案

### 目标
设计可直接交付开发的技术架构，冻结技术选型。

### 内容
- 系统整体技术架构（Mermaid 架构图）
- 各层技术选型及理由
- 数据模型设计
- 部署架构
- 集成方案
- 外部资源需求清单

### 设计理由
技术选型一旦确定并开始编码，修改成本会迅速上升。本阶段在编码前冻结技术栈，避免后续反复切换。

---

## 阶段四：准备开发

### 目标
建立不可轻易变更的规范边界，防止 AI 编程失控。

### 核心产出：`docs/architecture.md`

这份文档被称为"开发宪法"，包含：
- 技术栈清单（最终确定）
- 目录结构约定
- 数据模型概要
- 服务层约定
- AI 引用规则（限定可引入的依赖）
- 开发约束（命名规范、代码风格）
- 禁止破坏的核心逻辑
- 验收标准

### 设计理由
AI 编程的一个常见问题是"过度发挥"——AI 擅自引入未声明的库、修改核心逻辑、或创建不符合架构的代码。本阶段通过明确的约束边界来防止这些问题。

---

## 阶段五：正式开发

### 目标
按任务清单顺序，安全可控地完成所有模块开发。

### 小步迭代模式

每一轮迭代的对话模板：

```
📌 修改目标：本任务完成什么
📁 允许修改范围：可修改的文件或模块列表
🚫 不允许破坏的逻辑：参照 architecture.md 中的核心逻辑
⚡ 对其它模块的影响：预估影响范围及缓解措施
✅ 验收标准：如何算完成任务
🧪 单元测试计划：打算如何验证
```

### 验收标准
每个任务完成后，必须通过：
- 主流程测试
- 加载中状态
- 空数据状态
- 接口报错/异常状态
- 单元测试

### 设计理由
AI 一次处理大量代码时，容易出现"局部正确、整体错误"的情况。小步迭代模式通过限制单次修改范围，让每次修改都可审查、可验证、可回滚。

---

## 阶段六：系统测试

### 目标
确保产品质量达到可交付标准。

### 内容
1. 全量代码审查
2. 单元测试执行与补充
3. 需求回溯（逐条对照 PRD）
4. 整体验收（正常 + 异常 + 边界）
5. 生成 `docs/test-report.md`

### 设计理由
AI 生成的代码往往只覆盖"快乐路径"。本阶段通过系统化的测试覆盖，确保产品在真实场景下的可靠性。

---

## 阶段七：部署上线

### 目标
确保代码与文档一致，规范化交付。

### 内容
1. 文档同步（实际目录结构、环境变量、部署方式）
2. 生成最终 README.md
3. Git 提交 + 版本标签

### 设计理由
AI 开发容易产生"代码做了、文档没更新"的问题。本阶段通过强制文档同步，确保交付物完整可用。

---

## 全局规则

### 修改回溯规则
任何阶段，如果开发者提出修改上一阶段的内容，Claude 必须：
1. 更新对应文档
2. 重新取得确认
3. 再继续当前阶段

### 单任务聚焦
始终保持"一次只做一件事"的原则，禁止 AI 自由发挥超出规范范围。

### 输出物质量要求
- 所有 Mermaid 图表必须语法正确，可直接渲染
- 所有 HTML 原型必须可交互，在浏览器中可直接预览
- 所有代码必须可运行，通过测试
