# 使用指南

## 基本用法

在 Claude Code 中输入以下任一触发词，即可启动本 Skill 的工作流：

```
我有一个想法
我想做一个产品
帮我从零开发一个
我要从想法到上线
```

Claude 会按照 7 阶段流程逐步推进，**每阶段结束时需要你确认后再进入下一阶段**。

---

## 工作流交互概览

### 阶段一：产品定位

Claude 会依次向你提问，了解产品的目标用户、场景、核心功能等。你只需按真实想法回答即可。

**产出**：`docs/prd.md` — 产品需求说明书

### 阶段二：UI 原型设计

Claude 会：
1. 给出 3 种布局方案供你选择
2. 绘制 Mermaid 流程图确认交互流程
3. 提供 2-3 套配色方案供选择
4. 生成可交互的 HTML 原型（浏览器中可直接预览）
5. 输出设计规范文档

**产出**：`docs/design.md` + `docs/ui-prototypes/`

### 阶段三：技术方案

Claude 会询问你是否有偏好的技术栈，如无则根据产品形态推荐最佳方案。

**产出**：`docs/techsol.md` — 含架构图、选型理由、数据模型、部署方案

### 阶段四：准备开发

Claude 会锁定核心文档，生成不可轻易变更的架构规范。

**产出**：`docs/architecture.md` — 开发"宪法"

### 阶段五：正式开发

Claude 会生成 `TODO.md` 任务清单，按小步迭代模式逐项开发。每轮迭代前输出：

```
📌 修改目标：本任务完成什么
📁 允许修改范围：可修改的文件列表
🚫 不允许破坏的逻辑：不可修改的核心逻辑
⚡ 对其它模块的影响：预估影响范围
✅ 验收标准：如何算完成任务
🧪 测试计划：如何验证
```

你确认后，Claude 才会开始编码。

**产出**：`TODO.md` + 功能代码

### 阶段六：系统测试

全量代码审查、单元测试执行、需求回溯、整体验收。

**产出**：`docs/test-report.md`

### 阶段七：部署上线

文档同步、生成最终 README、Git 提交与版本标签。

**产出**：最终 README.md + 版本标签

## 关键操作指南

### 修改上一阶段内容

在任何阶段，如果你发现上一阶段的内容需要修改，直接提出即可。Claude 会：
1. 更新对应文档
2. 重新请你确认
3. 再继续当前阶段

### 查看当前进度

你可以随时问：
- "我们现在到哪个阶段了？"
- "当前进度如何？"

### 暂停或终止

Claude Code 原生支持暂停对话，下次继续时上下文会保留。

## 最佳实践

### ✅ 建议

- **回答要具体**：描述越详细，产出越准确
- **及时纠正**：发现方向不对立即指出，越早修正成本越低
- **确认前仔细阅读**：每阶段产出物确认前，花 1-2 分钟阅读一遍
- **保持一次一个想法**：不要在开发到一半时突然切换产品方向

### ❌ 避免

- **跳过阶段**：每个阶段都有其目的，跳过可能导致后续问题
- **同时推进多个功能**：小步迭代模式要求一次只做一个任务
- **频繁修改技术栈**：技术选型在阶段三冻结后，应尽可能遵守
